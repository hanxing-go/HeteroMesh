# 责任链模式与拦截器

## 一句话说清楚

**责任链 = 一串人排好队，每个人拿到请求后：自己处理一部分 → 交给下一个人 → 最后一个人真正干活。**

框架里叫「拦截器」或「过滤器」，本质上都是责任链模式的实现。

---

## 为什么要用？

没有拦截器时：

```java
// ClientHandler.handleTaskRequest() — 所有逻辑挤在一起
Object result = dispatcher.dispatch(invocation);  // 业务调用
// 想加日志？→ 改这里
// 想加鉴权？→ 改这里
// 想加限流？→ 改这里
// 两个月后：300 行，谁也看不懂
```

有了拦截器后：

```java
// 日志、鉴权、限流各自一个类，互不干扰
chain = RpcInterceptorChain.newBuilder()
    .addInterceptor(new AuthInterceptor())    // 鉴权
    .addInterceptor(new LogInterceptor())     // 日志
    .addInterceptor(new RateLimitInterceptor()) // 限流
    .handler(inv -> dispatcher.dispatch(inv)) // 最终干活的人
    .build();

Object result = chain.next(invocation);  // 一行触发整条链
```

**核心好处：每个横切关注点（日志、鉴权、限流）独立成一个类，新增逻辑不改旧代码。**

## 核心原理（用 HeteroMesh 代码讲）

### 三个角色

```java
// ① 接口 — 规矩
public interface RpcInterceptor {
    Object intercept(RpcInvocation inv, RpcInterceptorChain chain);
}

// ② 链 — 手里有拦截器列表 + 最终干活的人 + 一个计数器
public class RpcInterceptorChain {
    List<RpcInterceptor> interceptors;  // [LogInterceptor, AuthInterceptor]
    RpcHandler handler;                 // 最终干活的人
    int currentIndex = 0;               // 计数器，当前走到第几个

    public Object next(RpcInvocation inv) {
        if (currentIndex < interceptors.size()) {
            // 取下一个拦截器，索引+1，把自己(this)传进去
            return interceptors.get(currentIndex++).intercept(inv, this);
        } else {
            // 拦截器跑完了，干活
            return handler.handle(inv);
        }
    }
}

// ③ 具体拦截器 — 实现规矩
public class LogInterceptor implements RpcInterceptor {
    public Object intercept(RpcInvocation inv, RpcInterceptorChain chain) {
        log.info("→ 调用");
        Object result = chain.next(inv);  // ← 交出控制权
        log.info("← 完成");
        return result;
    }
}
```

### 一次调用的完整流程

假设链：`[LogInterceptor] → dispatcher`

```
ClientHandler:
  chain.next(inv)
    │  currentIndex=0 < 1 → 取 LogInterceptor，索引变 1
    │
    └→ LogInterceptor.intercept(inv, chain)
         │
         ├─ log.info("→ 调用")          // 前置处理
         │
         ├─ chain.next(inv)             // 交出控制权
         │    │  currentIndex=1 < 1? → false
         │    │
         │    └→ handler.handle(inv)    // 干活！
         │         └→ dispatcher.dispatch(inv)
         │              └→ 反射调用业务方法
         │              └→ return "处理完成"
         │
         ├─ log.info("← 完成 10ms")     // 后置处理
         │
         └─ return "处理完成"
```

**关键理解：** `LogInterceptor` 调 `chain.next(inv)` 不是递归调自己——它传进去的 `chain` 是同一个对象，但 `currentIndex` 已经变 1 了，所以 chain 知道自己该跳到下一个节点（handler）了。

### 拆开看「索引递增」的魔法

```
第 1 次 chain.next() → currentIndex=0 → 取 LogInterceptor，索引变 1
                        LogInterceptor 内部调 chain.next()
                            │
第 2 次 chain.next() → currentIndex=1 → 没拦截器了 → 调 handler

两次进的同一个方法，但因为索引变了，走的分支不同。
```

## 跟主流框架对比

| | Dubbo Filter | gRPC Interceptor | HeteroMesh |
|---|---|---|---|
| 接口 | `Filter.invoke(invoker, inv)` | `ServerInterceptor.interceptCall(call, headers, next)` | `RpcInterceptor.intercept(inv, chain)` |
| 链的串联方式 | 匿名类嵌套（倒序遍历构建） | 闭包装饰 | 索引递增（正序遍历） |
| 传给下一个 | `invoker.invoke(inv)` | `next.startCall(call, headers)` | `chain.next(inv)` |
| 前置/后置 | `invoke` 前后写 | 包装 Listener/Call | `chain.next()` 前后写 |
| 扩展方式 | SPI + `@Activate` | `ServerBuilder.intercept()` | Builder `addInterceptor()` |

三者本质一模一样——**拦截器拿到 next，调 next 就把球传下去了。**

### Dubbo 的实现（对比学习）

```java
// Dubbo 用倒序遍历 + 匿名类构建链：
Invoker<T> last = realInvoker;  // 最终干活的人
for (int i = filters.size() - 1; i >= 0; i--) {
    final Filter filter = filters.get(i);
    final Invoker<T> next = last;
    last = (inv) -> filter.invoke(next, inv);  // 当前 filter 持有 next
}
// 构建结果：filter1 → filter2 → filter3 → realInvoker
```

HeteroMesh 用 `currentIndex++` 正序遍历，效果完全一样，而且更容易理解——不用看匿名类和闭包。

## 常见错误

### 1. Chain 复用导致索引不重置

```java
// ❌ 同一个 chain 多次调用，第二次 currentIndex 已经在末尾
this.chain = RpcInterceptorChain.newBuilder()...build();
chain.next(inv1);  // OK，currentIndex 从 0 走到末尾
chain.next(inv2);  // BUG！currentIndex 还是末尾，拦截器全跳过

// ✅ 每次请求创建新 chain
RpcInterceptorChain chain = RpcInterceptorChain.newBuilder()...build();
chain.next(inv);
```

### 2. 拦截器忘了调 chain.next()

```java
// ❌ 拦截器吞了请求，链断裂
public Object intercept(RpcInvocation inv, RpcInterceptorChain chain) {
    log.info("拦截了");
    return "直接返回";  // 后面的拦截器和 handler 全不执行
}
```

### 3. 拦截器吞掉异常

```java
// ❌ catch 了异常不抛，调用方以为成功了
try { return chain.next(inv); }
catch (Exception e) { return null; }
```
