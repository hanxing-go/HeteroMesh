# HeteroMesh 后续课程总览

---

## 一、项目最终定位

HeteroMesh 最终不是一个只会通信的 RPC Demo，而是一个面向异构 Worker 的分布式任务调度系统。

但这不代表 RPC 不重要。RPC 是底层通信能力，任务调度系统是在 RPC、协议、连接治理、节点治理这些能力之上长出来的业务系统。

最终目标：

```text
Client 提交任务
Controller 创建任务、选择 Worker、追踪状态
Worker 执行任务并回传结果
Controller 保存结果、支持查询、重试、指标和演示
底层 RPC/协议/连接治理稳定支撑这条链路
```

面试时应能讲清楚：

```text
RPC 解决一次远程调用
任务调度解决任务生命周期
连接治理保证通信底座稳定
异构调度解决不同 Worker 资源差异
可观测性证明系统真实可运行
```

## 四、阶段一：任务调度闭环打磨

这个阶段目标是先把任务主链路建稳。

### 第22课：任务结果查询与任务管理服务

目标：

- 给 Controller 增加任务查询能力
- 支持按 `taskId` 查询任务详情
- 支持按状态过滤任务
- 支持列出所有任务
- 给后续 HTTP API 和 Dashboard 做准备

核心内容：

```text
TaskQueryService
TaskView / TaskDetailView
TaskStatus 过滤查询
任务不存在时的错误语义
```

完成标准：

```text
能通过 Java API 查询任务状态、结果、Worker、耗时、失败原因
```

---

### 第23课：任务级超时、取消与终态保护

目标：

- 区分 RPC 超时和任务超时
- Controller 提交任务后注册任务超时检查
- 超时任务进入 `TIMEOUT`
- 支持取消未完成任务
- 避免终态任务被后到结果覆盖

核心内容：

```text
TaskTimeoutManager
TaskCancellation
terminal status guard
late TASK_RESULT handling
```

完成标准：

```text
任务超时后状态变 TIMEOUT
取消任务后不会再被标记成功
后到的 Worker 结果不会覆盖终态
```

---

### 第24课：任务级重试与故障转移

目标：

- Worker 执行失败后支持换节点重试
- 使用 `attemptedWorkers` 排除失败节点
- 限制最大重试次数
- 区分可重试失败和不可重试失败
- 和现有熔断器、负载均衡协同

核心内容：

```text
TaskRetryPolicy
TaskRetryManager
retryable error
attempt history
```

完成标准：

```text
worker-A 执行失败后，任务可以自动转发给 worker-B
超过最大重试次数后任务进入 FAILED
每次尝试都有记录
```

## 五、阶段二：RPC 回炉与通信层补强

这个阶段专门回头过一遍 RPC。

安排在第24课之后，原因是：

```text
任务闭环已经跑通
我们已经真正看到了 RPC 和任务调度的边界
这时候再回头整理 RPC，不会只停留在抽象概念
```

### 第25课：RPC 全链路复盘与语义清理

目标：

- 重新阅读 RPC 全链路
- 梳理 `RpcProxy`、`RpcClient`、`RpcFuture`、`ClientHandler`、`ServerHandler`、`RpcDispatcher`
- 画清楚 `requestId` 的流转
- 明确 `Message.requestId`、`RpcRequest`、`RpcResponse` 的边界
- 清理误导性注释
- 规划 `TASK_REQUEST/TASK_RESPONSE` 到 `RPC_REQUEST/RPC_RESPONSE` 的迁移方案

核心内容：

```text
RPC call graph
requestId lifecycle
pendingRequests lifecycle
pendingClients lifecycle
RPC/Task message boundary
```

完成标准：

```text
你能不看代码讲清楚一次 RPC 从动态代理到响应回来的完整链路
代码注释不再把 RPC 请求叫成任务请求
```

这一课主要是重读、修文档、修命名语义和补关键测试，不急着大改协议枚举名。

---

### 第26课：RPC 连接治理与连接池

目标：

- 回到原第14课“连接池”未完成的内容
- 分析单连接异步多路复用和多连接池的区别
- 实现连接健康检查
- 实现断线重连策略
- 实现可选连接池
- 清理连接关闭后的 pending 请求

核心内容：

```text
ConnectionManager
ChannelHolder
SimpleChannelPool
ReconnectPolicy
pending request cleanup
connection health check
```

完成标准：

```text
连接断开后不会无限挂起请求
重连后可以继续发送 RPC
能解释什么时候需要连接池，什么时候单连接多路复用已经足够
```

面试价值：

```text
你不是只会用 Netty 发消息，而是理解长连接生命周期和连接池取舍
```

---

### 第27课：RPC 可靠性补强

目标：

- 完善 RPC 超时语义
- 完善异常码和错误响应
- 明确 one-way 调用行为
- 支持 RPC 调用取消或超时后的资源清理
- 检查熔断、限流、重试是否真的接在 RPC 主链路上

核心内容：

```text
RpcErrorCode
RpcException
RpcTimeout
RpcCancel
CircuitBreaker integration
RateLimiter integration
```

完成标准：

```text
RPC 调用失败时有明确错误类型
超时后 pendingRequests 一定清理
one-way 调用不会错误等待响应
熔断和限流不是孤立类，而是接入调用链路
```

面试价值：

```text
能讲清楚 RPC 框架的可靠性设计，而不是只有动态代理和反射调用
```

## 十一、什么时候重新过 RPC

明确安排：

```text
第24课完成后，立刻进入第25-27课 RPC 回炉阶段
```

为什么不是现在立刻做：

```text
第21-24课会把任务生命周期补完整
到那时 RPC 和任务调度的边界最清楚
再回头复盘 RPC，能避免只做抽象重构
```

为什么不能拖到最后：

```text
RPC 是底座
连接池、重连、pending 清理、异常语义如果不补强
后面的资源调度、HTTP API、集群演示都会被通信层问题拖住
```

## 十二、最终项目应能演示什么

最终演示路径：

```text
1. 启动 Controller
2. 启动多个 Worker
3. Worker 自动注册并心跳上报资源
4. 通过 HTTP 提交任务
5. Controller 按资源选择 Worker
6. Worker 执行任务并返回结果
7. 查询任务状态和结果
8. 模拟 Worker 失败
9. 任务自动重试或失败转移
10. Dashboard 展示任务和节点状态
11. 压测报告展示吞吐、延迟、瓶颈
```

最终你应该能讲清楚：

```text
协议如何设计
RPC 和任务调度如何分层
requestId 和 taskId 为什么不同
任务状态机如何保证合法流转
注册中心如何维护 Worker
调度器如何选择 Worker
连接池和重连如何设计
失败、超时、取消、重试如何处理
异构资源如何匹配
系统指标如何证明稳定性
项目还有哪些不足和后续优化
```
