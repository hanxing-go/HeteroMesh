# HeteroMesh 后续课程总览

---

## 一、路线原则

从第 16 课开始，项目目标不再是继续堆 RPC 组件，而是把 HeteroMesh 从：

```text
自研 RPC + 节点路由原型
```

推进成：

```text
可演示、可测试、可讲清楚的分布式任务调度系统
```

后续课程按三条标准设计：

1. **经得住面试追问**  
   每节课都要能回答：为什么这么设计？主流项目怎么做？失败场景怎么处理？

2. **核心代码由你手敲**  
   我提供教案、代码骨架、示例和 review。核心实现由你写。测试代码由我补，并写清楚测试意图。

3. **先闭环，再增强**  
   优先打通任务提交、调度、执行、回传、查询这条主链路。Dashboard、Docker、真实 GPU 推理放在后面。

## 三、后续课程总览

### 第 16 课：任务仓库 TaskStore

目标：

- 新增 `TaskStore` 接口
- 新增 `InMemoryTaskStore`
- 支持创建、查询、更新状态、绑定 Worker、记录尝试、写入结果、按状态过滤

核心产出：

```text
com.heteromesh.task.TaskStore
com.heteromesh.task.InMemoryTaskStore
```

面试价值：

> 我用 TaskStore 抽象任务状态存储，当前是内存实现，后续可替换 MySQL/Redis/etcd，调度器无需改动。

---

### 第 17 课：Controller 任务调度器 TaskScheduler

目标：

- 从 `ServerHandler` 中拆出任务调度逻辑
- `TaskScheduler` 接收 `TaskRequest`
- 创建任务元数据
- 选择 Worker
- 更新状态为 `DISPATCHING`
- 记录 `assignedWorkerId` 和 `attemptedWorkers`

核心产出：

```text
heteromesh-controller/src/main/java/com/heteromesh/controller/scheduler/TaskScheduler.java
heteromesh-controller/src/main/java/com/heteromesh/controller/scheduler/ScheduleResult.java
```

参考项目：

- XXL-JOB 调度中心
- Kubernetes Scheduler
- Spark Driver

面试价值：

> 我没有把调度逻辑写死在 Netty Handler 里，而是拆成 TaskScheduler，Handler 只负责协议入口，Scheduler 负责调度决策。

---

### 第 18 课：任务协议与 RPC 消息适配

目标：

- 将 `TASK_REQUEST` body 从泛泛的字符串/RpcRequest 逐步适配到 `TaskRequest`
- 明确 RPC 调用和任务调度的边界
- 支持 Controller 接收任务请求并保存任务状态

核心产出：

```text
TaskMessageCodec 或 TaskPayloadAdapter
TaskRequest <-> Message body 的转换逻辑
```

关键设计问题：

```text
RpcRequest 是“远程方法调用”
TaskRequest 是“调度任务”
两者不能长期混在一起
```

面试价值：

> 我区分了 RPC 框架层和任务调度层，避免把所有业务都塞进 RpcRequest。

---

### 第 19 课：WorkerTaskExecutor

目标：

- Worker 收到任务后，不再只反射调用 RPC 服务
- 增加本地任务执行器
- 支持任务进入 `RUNNING`
- 模拟执行任务并生成 `TaskResult`
- 将结果回传 Controller

核心产出：

```text
heteromesh-worker/src/main/java/com/heteromesh/worker/executor/WorkerTaskExecutor.java
heteromesh-worker/src/main/java/com/heteromesh/worker/executor/TaskExecutionContext.java
```

参考项目：

- XXL-JOB Executor
- Kubernetes Kubelet
- Spark Executor

面试价值：

> Worker 不只是一个 RPC 反射容器，而是有本地任务队列和执行器，能承载真实调度语义。

---

### 第 20 课：Controller 结果回收与任务闭环

目标：

- Controller 接收 `TaskResult`
- 更新 `TaskStore`
- 成功任务进入 `SUCCEEDED`
- 失败任务进入 `FAILED` 或触发重试
- 超时任务进入 `TIMEOUT`

核心产出：

```text
TaskResultHandler
TaskTimeoutManager
```

本课完成后的闭环：

```text
提交任务 -> 保存任务 -> 选择 Worker -> Worker 执行 -> 回传结果 -> 更新任务状态
```

面试价值：

> 我的调度系统能完整追踪任务生命周期，而不是只做请求转发。

---

### 第 21 课：任务级重试与故障转移

目标：

- 任务失败后选择新 Worker 重试
- 使用 `attemptedWorkers` 排除失败节点
- 限制最大重试次数
- 记录每次尝试
- 与已有熔断器协同

核心产出：

```text
RetryPolicy
TaskRetryManager
```

参考项目：

- Spark task retry
- Flink restart strategy
- Dubbo failover cluster

面试价值：

> 我把 RPC 层重试和任务层重试区分开。RPC 重试解决一次调用失败，任务重试解决调度执行失败。

---

### 第 22 课：HTTP API

目标：

- 用 Netty HTTP Server 暴露 REST API
- 支持提交任务
- 支持查询任务
- 支持查询节点列表
- 支持查询基础统计

核心端点：

```text
POST /api/tasks
GET  /api/tasks/{taskId}
GET  /api/tasks?status=RUNNING
GET  /api/nodes
GET  /api/metrics
```

核心产出：

```text
HttpApiServer
TaskSubmitHandler
TaskQueryHandler
NodeQueryHandler
MetricsHandler
```

参考项目：

- XXL-JOB Admin API
- Kubernetes API Server
- Spring Actuator

面试价值：

> 项目不只停留在单元测试，可以通过 HTTP API 真实提交和查询任务。

### 第 24 课：异构资源调度

目标：

- 根据 Worker 元数据做调度：
  - `gpuType`
  - `vramFree`
  - `weight`
  - `load`
- 根据 TaskRequest 的 `resourceRequirements` 筛选 Worker
- 在满足资源条件的节点中做负载均衡

核心产出：

```text
WorkerResourceMatcher
HeterogeneousTaskScheduler
WorkerLoadSnapshot
```

参考项目：

- Kubernetes NodeSelector / Resource Requests
- Volcano Scheduler
- vLLM Worker 调度思想

面试价值：

> HeteroMesh 的“异构”不是写在 README 里，而是真的能根据 GPU 类型、显存和负载做调度。

### 第 25 课：任务队列与背压

- Controller 端引入任务队列


- Netty write backpressure

面试价值：

> 我考虑了过载保护，不是 Client 发多少 Controller 就转发多少。

## 五、最终面试项目应该长什么样

最终你应该能演示：

```text
1. 启动 Controller
2. 启动 3 个 Worker
3. Worker 自动注册并心跳
4. 通过 HTTP API 提交任务
5. Controller 根据资源和负载选择 Worker
6. Worker 执行任务并回传结果
7. 查询任务状态和结果
8. 停掉一个 Worker
9. 新任务自动避开故障节点
10. 展示压测和指标数据
```

最终你应该能讲清：

```text
协议怎么设计
为什么要 SPI
为什么要 requestId + CompletableFuture
注册中心怎么维护节点
负载均衡怎么选
熔断和重试怎么配合
任务状态机怎么设计
任务失败怎么重试
异构 GPU 调度怎么做
系统指标怎么看
项目还有哪些不足
```

## 六、学习节奏

每节课都按这个节奏：

1. 我写教案
2. 你读教案
3. 你手敲核心代码
4. 我 review
5. 我补测试
6. 跑测试
7. 提交 GitHub
8. 开下一课

这条路线跑完，HeteroMesh 就不只是“写了很多 Java 类”，而是一个有主线、有闭环、有指标、有演示、有面试话术的项目。
