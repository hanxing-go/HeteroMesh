## 一、这节课解决什么问题？

### 1.1 当前问题

```
Client 只有一条连接连 Controller：

  RPC 调用 1 ──┐
  RPC 调用 2 ──┼──→ 一条 Channel ──→ Controller
  RPC 调用 3 ──┘

  100 个并发调用共享一条 TCP 连接 → 写操作排队 → 吞吐量受限
```

**连接池就是预先建立多条连接，借一个用一个，用完了还回去。**

```
Client 有一个连接池 [C1, C2, C3, C4, C5]：

  RPC 调用 1 → 借 C1 → 发请求 → 还 C1
  RPC 调用 2 → 借 C2 → 发请求 → 还 C2
  RPC 调用 3 → 借 C3 → 发请求 → 还 C3
  ...
  5 个并发各走各的 Channel，不排队
```

### 1.2 参考 Dubbo 的做法

Dubbo 默认「单一长连接」模式——Consumer 和 Provider 之间只维持一条 TCP 连接，通过异步多路复用承载所有请求。同时支持配置 `connections=N` 来使用多连接。

HeteroMesh 做一个简单的 ChannelPool，支持：
- 借连接（`acquire`）— 从池里拿一个空闲连接，池空了就创建新的（不超过上限）
- 还连接（`release`）— 用完了放回池里，等待下次被借
- 健康检查 — 还连接时检查 Channel 是否还活跃，不活跃就关闭丢弃
- 空闲驱逐 — 定时清理长时间没被使用的空闲连接

## 二、核心设计

### 2.1 数据结构

```
SimpleChannelPool:
  idleQueue: Deque<Channel>     ← 空闲连接队列（借走就移除，还回来就放回）
  activeCount: AtomicInteger    ← 当前池里的总连接数（空闲 + 借出中）
  maxConnections: int           ← 连接数上限
  bootstrap: Bootstrap          ← 创建新连接用的 Netty Bootstrap
```

### 2.2 借-还流程

```
acquire():
  idleQueue 不空？→ poll 一个出来 → 健康检查 → 健康就返回
  activeCount < max？ → 创建新连接 → activeCount++ → 返回
  都不行 → 返回 null（池已满且无空闲）

release(channel):
  channel 还活跃？ → idleQueue.offer(channel)
  不活跃 → close(channel) → activeCount--
```

### 2.3 空闲驱逐

后台线程定时扫描 `idleQueue`，把超过空闲时间的 Channel 关闭：

```
驱逐线程（每 30 秒执行一次）：
  for channel in idleQueue:
    if now - lastUsedTime > idleTimeout:
      idleQueue.remove(channel)
      channel.close()
      activeCount--
```

### 2.4 健康检查

```java
// 借出前检查
if (channel.isActive() && channel.isOpen()) {
    return channel;  // 健康
} else {
    activeCount--;    // 不健康，丢弃
    // 重新找下一个
}
```

## 三、你要写的核心代码

### 3.1 SimpleChannelPool（~80 行）

位置：`heteromesh-common/src/main/java/com/heteromesh/transport/SimpleChannelPool.java`

```java
package com.heteromesh.transport;

import io.netty.bootstrap.Bootstrap;
import io.netty.channel.Channel;
import lombok.extern.slf4j.Slf4j;

import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * 简易 Netty Channel 连接池。
 * 参考 Netty SimpleChannelPool + Dubbo 共享连接设计。
 *
 * 借-还模型 + 健康检查 + 空闲驱逐。
 */
@Slf4j
public class SimpleChannelPool {

    private final Bootstrap bootstrap;
    private final int maxConnections;
    private final long idleTimeoutMs;

    // 空闲连接队列（线程安全）
    private final Deque<PooledChannel> idleQueue = new ConcurrentLinkedDeque<>();
    // 当前总连接数
    private final AtomicInteger activeCount = new AtomicInteger(0);
    // 定时驱逐线程
    private final ScheduledExecutorService evictor;

    public SimpleChannelPool(Bootstrap bootstrap, int maxConnections, long idleTimeoutMs) {
        this.bootstrap = bootstrap;
        this.maxConnections = maxConnections;
        this.idleTimeoutMs = idleTimeoutMs;
        this.evictor = Executors.newSingleThreadScheduledExecutor(r -> {
            Thread t = new Thread(r, "channel-pool-evictor");
            t.setDaemon(true);
            return t;
        });
        // 每 30 秒执行一次空闲驱逐
        evictor.scheduleWithFixedDelay(this::evict, 30, 30, TimeUnit.SECONDS);
    }

    /** 借一个连接 */
    public Channel acquire() throws Exception {
        // ① 先从空闲队列拿
        PooledChannel pc;
        while ((pc = idleQueue.poll()) != null) {
            Channel ch = pc.channel;
            if (ch.isActive() && ch.isOpen()) {
                return ch;  // 健康，返回
            }
            activeCount.decrementAndGet();  // 不健康，丢弃
        }

        // ② 池未满 → 创建新连接
        if (activeCount.get() < maxConnections) {
            Channel ch = bootstrap.connect().sync().channel();
            activeCount.incrementAndGet();
            return ch;
        }

        // ③ 池满了，等别人还回来
        return null;  // 调用方可以阻塞等待或稍后重试
    }

    /** 还连接 */
    public void release(Channel channel) {
        if (channel != null && channel.isActive() && channel.isOpen()) {
            idleQueue.offer(new PooledChannel(channel, System.currentTimeMillis()));
        } else if (channel != null) {
            channel.close();
            activeCount.decrementAndGet();
        }
    }

    /** 关闭连接池 */
    public void close() {
        evictor.shutdown();
        PooledChannel pc;
        while ((pc = idleQueue.poll()) != null) {
            pc.channel.close();
        }
    }

    /** 空闲驱逐 */
    private void evict() {
        long now = System.currentTimeMillis();
        idleQueue.removeIf(pc -> {
            if (now - pc.lastUsedTime > idleTimeoutMs) {
                pc.channel.close();
                activeCount.decrementAndGet();
                log.debug("驱逐空闲连接: {}", pc.channel.id());
                return true;
            }
            return false;
        });
    }

    /** 内部包装：Channel + 最后使用时间 */
    private record PooledChannel(Channel channel, long lastUsedTime) {}
}
```

### 3.2 RpcClient 改造

把 RpcClient 里存单个 `Channel` 改成存 `SimpleChannelPool`，不再直连：

```java
// 改前
public class RpcClient {
    private final Channel channel;  // 单连接
}

// 改后
public class RpcClient {
    private final SimpleChannelPool pool;  // 连接池
    
    public CompletableFuture<Message> call(String body, String requestId) {
        Channel ch = pool.acquire();  // 借连接
        Message request = new Message(MessageType.TASK_REQUEST, requestId, body);
        CompletableFuture<Message> future = new CompletableFuture<>();
        pendingRequests.put(requestId, future);
        ch.writeAndFlush(request).addListener(f -> {
            // 响应回来后还连接
        });
        return future;
    }
}
```

**但要小心**：当前 `pendingRequests` + `onResponse` 机制依赖同一个 Channel 收响应。用连接池后，多个 Channel 的响应都到达同一个 `ClientHandler`，`onResponse` 仍然能正确匹配（通过 requestId）。

## 五、常见错误预警

### 错误 1：借出后忘了还

```java
// ❌ 用完不还 → 连接泄漏
Channel ch = pool.acquire();
ch.writeAndFlush(msg);
// 忘了 release！这个连接永远不会回到池里

// ✅ finally 里还
Channel ch = pool.acquire();
try {
    ch.writeAndFlush(msg);
} finally {
    pool.release(ch);
}
```

### 错误 2：还连接时没检查健康

```java
// ❌ 不管死活直接丢回池
idleQueue.offer(channel);

// ✅ 先检查，不健康的关闭掉
if (channel.isActive() && channel.isOpen()) {
    idleQueue.offer(channel);
} else {
    channel.close();
    activeCount--;
}
```

### 错误 3：驱逐线程没设守护

```java
// ❌ 非守护线程 → JVM 无法正常退出
new Thread(evictTask).start();

// ✅ 设为守护线程
Thread t = new Thread(evictTask);
t.setDaemon(true);
t.start();
```

### 错误 4：并发借同一个空闲连接

```java
// ❌ 普通 Deque 的 poll 不是线程安全的
private final Deque<Channel> idleQueue = new ArrayDeque<>();

// ✅ ConcurrentLinkedDeque，poll/offer 都是原子的
private final Deque<PooledChannel> idleQueue = new ConcurrentLinkedDeque<>();
```

> "第 14 课我写了一个简易 Netty 连接池，支持借-还模型、健康检查和空闲驱逐。参考 Netty 的 SimpleChannelPool 和 Dubbo 的共享连接设计。借连接时先从空闲队列拿，不健康就丢弃；空闲队列空就创建新连接（不超过上限）；还连接时检查 Channel 还活着就放回池里，死了就关闭。"

> "空闲驱逐用守护线程定时扫描，超过空闲时间的连接直接关闭。为什么用 ConcurrentLinkedDeque？poll/offer 都是 CAS 无锁操作，借还的高频路径不需要加锁。"

> "Dubbo 的共享连接更进一步——用引用计数保证只要还有服务在使用这个 Provider 的连接就不会被关闭。HeteroMesh 的连接池更简单，没有引用计数，借还就是纯 queue 操作。"
