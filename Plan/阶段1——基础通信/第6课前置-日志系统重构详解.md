# 第 1 课（新计划）：日志系统重构

## 一、为什么 System.err.println 不行？

你现在项目里有 4 处用 `System.err.println` / `System.out.println`：

```java
// ExceptionHandler.java
System.err.println("链接断开" + ctx.channel() + cause.getMessage());
cause.printStackTrace();  // ← 直接打到 stderr

// RpcClient.java
System.err.println("[RpcClient] 收到未知响应，requestId=" + ...);

// ServerHandler.java
System.out.println("收到消息: "+ message.getBody());

// ClientHandler.java
System.out.println(response.getBody());
System.out.println("收到回复:" + msg.getBody());
```

这些在开发时没问题，但作为你未来的"简历项目"是**不可接受的**。原因：

| 问题 | System.err/out | SLF4J |
|------|---------------|-------|
| **没有日志级别** | 所有输出一样 | DEBUG < INFO < WARN < ERROR，可动态调整 |
| **没有类名/行号** | 只输出文本 | 自动带 `[ClassName.java:42]` |
| **没有时间戳** | 无 | 自动带 `14:23:15.123` |
| **没有线程名** | 无 | 自动带 `[nioEventLoop-3-1]` |
| **无法输出到文件** | 要重定向 | 一行配置搞定 |
| **生产环境没法关** | 关键字都在代码里 | 改 logback.xml，一行不改 |

**面试官看代码，第一眼看到 `System.out` 和 `e.printStackTrace()` 就知道：这人没写过生产代码。**

## 二、SLF4J 是什么？

**Simple Logging Facade for Java** — 日志门面。

```
你的代码 → SLF4J (门面接口) → Logback (实际干活)
           ↑ 你只依赖这个    ↑ 想换就换
           永远不变          换 Log4j2 只需改 pom.xml
```

类比：SLF4J = USB 接口，Logback = U 盘。你只插 USB 口，用什么 U 盘换个就行。

你的项目已经配好了 SLF4J + Logback：

```xml
<!-- pom.xml 已有 -->
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>slf4j-api</artifactId>        <!-- 门面接口 -->
</dependency>
<dependency>
    <groupId>ch.qos.logback</groupId>
    <artifactId>logback-classic</artifactId>  <!-- 实际干活 -->
</dependency>
```

## 三、日志级别

从低到高，5 个级别：

```
TRACE → DEBUG → INFO → WARN → ERROR → 关闭
  ↑       ↑       ↑      ↑       ↑
 最啰嗦   调试    正常   警告    错误
         信息    信息
```

你在 `logback.xml` 里设 `root level="INFO"`，那么：
- `log.info("xxx")` → 输出 ✅
- `log.warn("xxx")` → 输出 ✅
- `log.error("xxx")` → 输出 ✅
- `log.debug("xxx")` → 忽略 ❌（级别不够）
- `log.trace("xxx")` → 忽略 ❌

**开发时改 DEBUG 看详细日志，上线改 INFO/WARN。一行配置，不用改代码。**

## 四、@Slf4j 注解

Lombok 提供的注解，编译时自动生成 `log` 变量：

```java
// 你写这个
@Slf4j
public class ExceptionHandler extends ChannelInboundHandlerAdapter {
    public void exceptionCaught(...) {
        log.error("连接断开: channel={}, msg={}", ctx.channel(), cause.getMessage(), cause);
    }
}

// Lombok 编译后自动变成
public class ExceptionHandler extends ChannelInboundHandlerAdapter {
    private static final org.slf4j.Logger log =
        org.slf4j.LoggerFactory.getLogger(ExceptionHandler.class);
    // 你的代码...
}
```

**log.error("连接断开: channel={}, msg={}", ctx.channel(), cause.getMessage(), cause)**

注意写法：
- ❌ **不要**：`log.error("连接断开: " + ctx.channel() + cause.getMessage())` ← 字符串拼接，每次都执行
- ✅ **要**：`log.error("连接断开: channel={}, msg={}", ctx.channel(), cause.getMessage())` ← 占位符，DEBUG 级别时才拼接

占位符 `{}` = 参数替换，由 SLF4J 内部做，只在日志实际输出时才拼接字符串。省 CPU。

## 五、printStackTrace() 的替代方案

`cause.printStackTrace()` 把堆栈打到 `System.err`。SLF4J 的方式：

```java
// 有异常对象时，最后一个参数直接放 Throwable
log.error("处理消息时发生异常", cause);  // ← SLF4J 会自动打印堆栈
```

## 六、你的 logback.xml（已有，不用动）

```xml
<configuration>
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <logger name="com.heteromesh" level="DEBUG"/>   <!-- 你的代码打 DEBUG 以上 -->
    <logger name="io.netty" level="INFO"/>           <!-- Netty 只打 INFO 以上 -->

    <root level="INFO">
        <appender-ref ref="STDOUT"/>
    </root>
</configuration>
```

`%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n` 会输出：

```
14:23:15.123 [nioEventLoopGroup-3-1] ERROR c.h.transport.ExceptionHandler - 连接断开: ...
```

自动包含：时间、线程名、级别、类名、消息。

## 七、你要改什么

### 1. ExceptionHandler.java

```java
// 改前
catch (IOException e) {
    System.err.println("链接断开" + ctx.channel() + cause.getMessage());
} else {
    cause.printStackTrace();
}

// 改后
@Slf4j
public class ExceptionHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
        if (cause instanceof IOException) {
            log.warn("连接断开: channel={}", ctx.channel().id().asShortText(), cause);
        } else {
            log.error("未预期的异常: channel={}", ctx.channel().id().asShortText(), cause);
        }
        ctx.close();
    }
}
```

关键变化：
- `System.err.println` → `log.warn(..., cause)` — cause 放到最后，SLF4J 自动打印堆栈
- `cause.printStackTrace()` → `log.error(..., cause)` — 同上，但还能看到是哪个 channel
- 新增 `channel.id().asShortText()` — 日志里能区分是哪个连接

### 2. RpcClient.java

```java
// 改前
System.err.println("[RpcClient] 收到未知响应，requestId=" + response.getRequestId());

// 改后
@Slf4j
public class RpcClient {
    // ...
    log.warn("收到未知响应，无法匹配到待处理请求: requestId={}", response.getRequestId());
}
```

### 3. ServerHandler.java

```java
// 改前

// 改后
@Slf4j
public class ServerHandler extends SimpleChannelInboundHandler<Message> {

```

## 八、HeartbeatHandler 新增的日志

```java
@Slf4j
public class HeartbeatHandler extends ChannelInboundHandlerAdapter {
    
    @Override
    public void userEventTriggered(ChannelHandlerContext ctx, Object evt) {
        if (evt instanceof IdleStateEvent) {
            IdleStateEvent e = (IdleStateEvent) evt;
            if (e.state() == IdleState.ALL_IDLE) {
                int count = beatCnt.incrementAndGet();
                if (count > MAX_MISSED) {
                    log.warn("心跳超时: channel={}, 连续{}次未回复, 关闭连接",
                            ctx.channel().id().asShortText(), count);
                    ctx.close();
                    return;
                }
                log.debug("发送 PING: channel={}, count={}",
                        ctx.channel().id().asShortText(), count);
                ctx.writeAndFlush(Message.createPing());
            }
        }
    }
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object o) {
        Message msg = (Message) o;
        if (msg.getType() == MessageType.PING) {
            log.debug("收到 PING, 回复 PONG: channel={}",
                    ctx.channel().id().asShortText());
            ctx.writeAndFlush(Message.createPong());
            beatCnt.set(0);
        } else if (msg.getType() == MessageType.PONG) {
            log.debug("收到 PONG, 重置计数器: channel={}",
                    ctx.channel().id().asShortText());
            beatCnt.set(0);
        } else {
            ctx.fireChannelRead(msg);
        }
    }
}
```
